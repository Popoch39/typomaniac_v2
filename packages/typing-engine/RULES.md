# Typing engine rules

This document lists every rule that `@repo/typing-engine` applies, with its identifier and the Monkeytype function it comes from. Test names reuse these identifiers.

## Reference

- Monkeytype at commit `66cda5ca1b138bd786d3c7c43a8ae606da98978e`. Paths below start from `frontend/src/ts/` in that repository, unless stated otherwise.
- Monkeytype is under GPL-3.0. This package describes its rules and rewrites them from scratch: neither its code nor its tests are copied (see ADR 0003).
- A rule marked "Typomaniac" has no source in Monkeytype: it comes from the shape of the engine.

## Monkeytype default settings

The engine applies Monkeytype's default settings and exposes none of them. Values read in `constants/default-config.ts` at the reference commit:

| Setting         | Key              | Default    | Effect of the default on the rules                                                                                                                  |
| --------------- | ---------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Quick end       | `quickEnd`       | `false`    | The last word does not end the Game as soon as it reaches the target length: it must be exact, or a Separator must validate it (`checkIfFinished`). |
| Strict space    | `strictSpace`    | `false`    | A space on an empty input is refused before insertion (`onBeforeInsertText`): it does not skip the word and does not count as a mistake.            |
| Stop on error   | `stopOnError`    | `"off"`    | An incorrect insertion stays in the input, and a space validates a word even if it is wrong (`shouldGoToNextWord`).                                 |
| Confidence mode | `confidenceMode` | `"off"`    | Backspace is never blocked by this mode (`onBeforeDelete`).                                                                                         |
| Freedom mode    | `freedomMode`    | `false`    | Going back to the previous word stays reserved for an incorrect previous word (`onBeforeDelete`).                                                   |
| Difficulty      | `difficulty`     | `"normal"` | No mistake fails the Game (`checkIfFailedDueToDifficulty`), and a space on an empty input stays refused.                                            |
| Delete on error | `deleteOnError`  | `"off"`    | Recorded because `checkIfFinished` and `shouldGoToNextWord` depend on it: no automatic deletion after a mistake.                                    |

None of these values contradicts the spec. `quickEnd` at `false` does not delay the end of a Game without mistakes: `checkIfFinished` ends the Game as soon as the input of the last word is exactly that word, whatever this setting.

## Input

| Id      | Rule                                                                                                                                                                                                                                                             | Source                                                                                                                      |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| START-1 | Without a Start, the clock starts at the first text insertion, at the timestamp of that insertion.                                                                                                                                                               | `input/handlers/insert-text.ts` → `onInsertText` (call to `TestLogic.startTest(now)`)                                       |
| INS-1   | A correct insertion, meaning the character expected at that position of the Target word, is appended to the input of the active word.                                                                                                                            | `input/helpers/validation.ts` → `isCharCorrect`                                                                             |
| INS-2   | The Separator expected at the end of a word validates the word: it is appended to the input, and the next word becomes the active word.                                                                                                                          | `input/helpers/validation.ts` → `shouldGoToNextWord` ; `input/helpers/word-navigation.ts` → `goToNextWord`                  |
| INS-3   | A multi-character insertion is applied character by character, all at the same timestamp.                                                                                                                                                                        | `input/handlers/insert-text.ts` → `onInsertText` (`data.length > 1` branch)                                                 |
| INS-4   | An insertion that is not the character expected at that position of the Target word, Separator included, is incorrect and stays in the input. Beyond the target, every insertion is incorrect.                                                                   | `input/helpers/validation.ts` → `isCharCorrect`                                                                             |
| INS-5   | A space on an empty input is refused: the Game does not change, the clock does not start and no Keystroke is recorded.                                                                                                                                           | `input/handlers/before-insert-text.ts` → `onBeforeInsertText`                                                               |
| INS-6   | A space on a non-empty input validates the word, whether right, wrong or incomplete: it is appended to the input and the next word becomes the active word. It is judged like any insertion: correct if it lands at the Separator position, incorrect otherwise. | `input/helpers/validation.ts` → `shouldGoToNextWord`, `isCharCorrect` ; `input/helpers/word-navigation.ts` → `goToNextWord` |
| INS-7   | The input of a word is capped at the length of the Target word, Separator included, plus 20. At the cap, an insertion is refused without leaving a Keystroke, except the space, which always validates the word.                                                 | `input/handlers/before-insert-text.ts` → `onBeforeInsertText`                                                               |
| INS-8   | The 14 recognized space characters (list below) are replaced by an ordinary space before being judged: the input and the Keystroke log contain only U+0020. Any other whitespace is an ordinary character.                                                       | `utils/strings.ts` → `isSpace` ; `input/helpers/util.ts` → `normalizeData`, `getCommitCharacterType`                        |

Recognized space characters (INS-8): U+0020, U+00A0, U+1680, U+2002, U+2003, U+2004, U+2007, U+2008, U+2009, U+200A, U+200B, U+202F, U+3000, U+FEFF. U+2000, U+2001, U+2005, U+2006, U+205F, the tab and the line feed are not part of it.

Active word: during the Game, Monkeytype keeps a counter that `goToNextWord` increments each time a word that has a successor is validated; `test/events/stats.ts` → `inferActiveWordIndex` recovers the same value from the log. The engine keeps this counter in the Game (GAME-1, INS-6).

Deviation from the text of ticket #8, pending an answer from the spec author. It follows Monkeytype and is reversed at the place indicated:

- **INS-7, space accepted at the cap.** The ticket says an insertion beyond the cap is refused, with no exception. `onBeforeInsertText` only refuses an insertion at the cap if it does not move on to the next word: the space is therefore always accepted there, it validates the word and leaves a Keystroke, and the input can then reach the target length plus 21. Without this, a word that has reached the cap could only be left by a deletion. The engine does as Monkeytype does. To go back to the text: the cap condition in `insertChar` (`src/game.ts`), removing the space exception.

Known deviations on input:

- `normalizeData` also replaces a character "visually equal" to the expected one (families of apostrophes, quotes, dashes and commas) with the expected character, and `onInsertText` expands the ellipsis character into three dots. The spec says nothing about it: the engine does not do it.
- `onBeforeInsertText` refuses a line feed when the words contain none. The engine judges it as an ordinary character, so incorrect.

## Corrections

A deletion applies to a character or to a word. Both follow the same condition to go back to the previous word: `onBeforeDelete` does not look at the type of deletion. Point re-read at the reference commit, as the spec requested.

| Id    | Rule                                                                                                                                                                                                                                                                   | Source                                                                                                         |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| DEL-1 | A character deletion removes the last character of the input of the active word.                                                                                                                                                                                       | `input/handlers/delete.ts` → `onDelete` ; `test/events/helpers.ts` → `applyInputEvent`                         |
| DEL-2 | On the first word with an empty input, a deletion, of a character or of a word, is ignored.                                                                                                                                                                            | `input/handlers/before-delete.ts` → `onBeforeDelete`                                                           |
| DEL-3 | On an empty input, a character deletion goes back to the previous word if it is incorrect, meaning its input differs from its Target word, Separator included. That word becomes the active word again, with its input minus the trailing space that had validated it. | `input/handlers/before-delete.ts` → `onBeforeDelete` ; `input/helpers/word-navigation.ts` → `goToPreviousWord` |
| DEL-4 | On an empty input, a deletion, of a character or of a word, is ignored if the previous word was typed exactly.                                                                                                                                                         | `input/handlers/before-delete.ts` → `onBeforeDelete`                                                           |
| DEL-5 | A word deletion removes from the input of the active word the last block of non-blank characters with the blanks that follow it, or failing that the trailing blanks.                                                                                                  | `test/events/helpers.ts` → `applyInputEvent`                                                                   |
| DEL-6 | On an empty input, a word deletion goes back to the previous word under the same condition as DEL-3, and empties its input.                                                                                                                                            | `input/handlers/before-delete.ts` → `onBeforeDelete` ; `input/helpers/word-navigation.ts` → `goToPreviousWord` |
| DEL-7 | A deletion neither adds a Keystroke to the log nor removes one.                                                                                                                                                                                                        | `input/handlers/delete.ts` → `onDelete` (deletion is a separate event, the log's insertions stay in place)     |
| DEL-8 | An incorrect Keystroke that is then erased still counts as incorrect in the Accuracy (ACC-1): deletions do not count there.                                                                                                                                            | `test/events/stats.ts` → `getAccuracy`                                                                         |
| DEL-9 | The character count (CHARS-1 to CHARS-5) applies to the final input of each word: a word that is corrected then validated exactly counts in the WPM (RES-2).                                                                                                           | `test/events/stats.ts` → `getChars`, `countCharsForWordIndex`                                                  |

A deletion applied to a finished Game does not modify it (END-2); `onBeforeDelete` also refuses it as long as the Game has not started, which DEL-2 already covers since the input is then empty on the first word. A deletion neither starts the clock nor resets it.

Active word after going back: `goToPreviousWord` decrements Monkeytype's counter; the engine does the same with the index of the active word (GAME-1).

Known deviations on corrections:

- In Monkeytype, it is the browser that decides what a word deletion removes from the live input; `applyInputEvent` is its pure model, which DEL-5 follows. With the default settings, a recognized space (INS-8) always validates the word: only a blank outside that list, such as the tab, can end up in an input.
- `onBeforeDelete` refuses going back to a previous word that is no longer displayed. That is a layout rule, out of scope: the front applies it by not emitting the Event.
- Monkeytype does not record a Keystroke for a deletion but keeps it in its event log, with the resulting input. The engine's public log contains only insertions (KEY-1).

## Keystroke log

| Id    | Rule                                                                                                                                                                                                                                        | Source                                                                    |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| KEY-1 | The Game exposes the log of its Keystrokes: one entry per judged insertion, with its instant, the word index, the position in the word (the length of the input before the insertion), the character after INS-8 and whether it is correct. | `input/handlers/insert-text.ts` → `onInsertText` (call to `logTestEvent`) |
| KEY-2 | A refused insertion (INS-5, INS-7) leaves no entry in the log.                                                                                                                                                                              | `input/handlers/before-insert-text.ts` → `onBeforeInsertText`             |

Known deviation on KEY-1: Monkeytype timestamps a Keystroke relative to the start of the Game. The engine keeps the client timestamp carried by the Event, as for the start and the end of the Game.

## End of Game

| Id    | Rule                                                                                                                                                                                              | Source                                                                                                                  |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| END-1 | In `words` Mode, the Game ends as soon as the input of the last word is exactly that word, without a trailing space. The end instant is that of the insertion.                                    | `input/helpers/fail-or-finish.ts` → `checkIfFinished`                                                                   |
| END-2 | An Event applied to a finished Game does not modify it, including the characters of an insertion that follow the one that ends the Game.                                                          | `input/handlers/before-insert-text.ts` → `onBeforeInsertText` (`isResultCalculating`)                                   |
| END-3 | In `words` Mode, a space on the last word, wrong or incomplete but non-empty, ends the Game at the instant of that space. The space is removed from the input but remains an incorrect Keystroke. | `input/helpers/fail-or-finish.ts` → `checkIfFinished` ; `test/events/helpers.ts` → `applyInputEvent`, `getInputFromDom` |

Known deviation on END-1: Monkeytype timestamps the end with a fresh call to `performance.now()` in `test/test-logic.ts` → `finish`, a few fractions of a millisecond after the last insertion. The engine has no clock: it takes the timestamp of the insertion that ends the Game.

## Result

## Character count

The Result compares each word to its Target word, position by position, up to the longer of the input and the target. Common source: `test/events/stats.ts` → `getChars`, `countCharsForWordIndex` ; `utils/strings.ts` → `countChars`.

| Id      | Rule                                                                                                                                                                                                                  |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CHARS-1 | A character identical to the target's at its position is correct. If the input of the word is exactly the Target word, its characters, Separator included, are also counted as characters of the words typed exactly. |
| CHARS-2 | A character different from the target's at its position is incorrect.                                                                                                                                                 |
| CHARS-3 | The Separator of a wrong word is incorrect, even typed at its position.                                                                                                                                               |
| CHARS-4 | A character typed beyond the target is extra, the space that validates the word included. A letter typed at the Separator position of a validated word is incorrect.                                                  |
| CHARS-5 | A target position with no typed character is missed: the end of a word validated too early, a skipped word, the unfinished last word of a `words` Game.                                                               |

Known deviations on the count:

- The Accuracy and the count do not judge the space of a wrong word the same way: typed at the Separator position, it is a correct Keystroke (INS-6) but an incorrect character (CHARS-3). That is Monkeytype's behavior.
- `countChars` counts as extra, not incorrect, a letter typed at the Separator position of a word that has not been validated, and as extra a correct space that did not validate the word. The first case is reachable on the active word of a `time` Game: that is CHARS-8. The second is not, since a space on a non-empty input always validates the word (INS-6): the engine does not code it.

## `time` Mode

The rules above apply in both Modes, except SEP-1, END-1 and END-3 which apply to the last word of a `words` Game: a `time` Game has no last word.

| Id     | Rule                                                                                                                                                                                       | Source                                                                                           |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| GAME-4 | In `time` Mode, the Game is created with a duration in seconds and keeps all the words of the list.                                                                                        | `test/test-timer.ts` → `checkIfTimeIsUp` (`Config.time`)                                         |
| GAME-5 | Creating a `time` Game is refused if the duration is not a strictly positive finite number.                                                                                                | Typomaniac (Monkeytype's endless `time` Mode, `time = 0`, is out of scope)                       |
| SEP-2  | In `time` Mode, all Target words carry a Separator, including the last one of the current list and the added words.                                                                        | `test/words-generator.ts` → `areAllWordsGenerated`, `appendCommitCharacter`                      |
| ADD-1  | An addition of words extends the list of Target words, with an empty input per added word. It touches neither the inputs, nor the active word, nor the status, nor the clock, nor the log. | `test/test-logic.ts` → `addWord` ; `test/test-words.ts` → `Words.push`                           |
| ADD-2  | In `words` Mode, an addition of words is ignored: the last word has no Separator, nothing can follow it.                                                                                   | Typomaniac                                                                                       |
| ADD-3  | In `time` Mode, validating the last available word does not end the Game: the active word moves past the list, and every insertion is refused without a Keystroke until words are added.   | Typomaniac, after `input/helpers/word-navigation.ts` → `goToNextWord` (see the assumption below) |
| TICK-1 | A Tick received before the clock has started neither starts nor ends the Game.                                                                                                             | `test/test-logic.ts` → `startTest` (the timer only exists once the Game has started)             |
| TICK-2 | In `time` Mode, a Tick whose time elapsed since the start does not reach the limit does not change the Game.                                                                               | `test/test-timer.ts` → `timerStep`, `checkIfTimeIsUp`                                            |
| TICK-3 | In `words` Mode, a Tick never ends the Game.                                                                                                                                               | `test/test-timer.ts` → `checkIfTimeIsUp`                                                         |
| END-4  | In `time` Mode, the Game ends at the first Tick whose time elapsed since the start reaches the limit. The end instant is that of this Tick: the duration (RES-1) can exceed the limit.     | `test/test-timer.ts` → `timerStep`, `checkIfTimeIsUp`, `clear` ; `test/test-logic.ts` → `finish` |
| END-5  | The Keystrokes that arrived after the limit but before the Tick that ends the Game count in the input, the log and the Result.                                                             | `test/events/data.ts` → `cleanupData`                                                            |

Character count of a `time` Game, same common source as CHARS-1 to CHARS-5:

| Id      | Rule                                                                                                                                                                                                                        |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CHARS-6 | In `time` Mode, the untyped characters of the active word are not missed, and if its input is a correct beginning of the Target word, its characters are counted as characters of the words typed exactly, so in the WPM.   |
| CHARS-7 | In `time` Mode, an active word whose input is not a correct beginning of the Target word contributes no character to the WPM, not even its first right letters. Its characters count in the Raw WPM like those of any word. |
| CHARS-8 | A letter typed at the Separator position of a word that no space has validated is extra, and not incorrect as for a validated word (CHARS-4).                                                                               |
| CHARS-9 | The words after the active word are not counted: none of their characters is missed.                                                                                                                                        |

Assumption on ADD-3: Monkeytype keeps about a hundred generated words ahead of the active word, so the active word is never the last of the list in `time` Mode there. The engine receives its words through an Event, so the case can happen. `goToNextWord` then blocks input while waiting for the next word: the engine likewise refuses insertions, without a Keystroke and without starting the clock, and the caller is expected to add words before reaching that point. The validated word keeps its space in the input and is counted like any validated word.

Known deviations on `time` Mode:

- Monkeytype counts its Ticks on a one-second grid anchored at the start and ends the Game at the Tick whose number reaches the limit. A Tick is never processed there before its grid instant: it is the same instant as "the first Tick whose time elapsed reaches the limit" (END-4). The engine does not count Ticks, it compares the Tick's timestamp to the start.
- Monkeytype timestamps the end with `performance.now()` in `finish`. The engine takes the timestamp of the Tick that ends the Game.

## Start on signal

The Start is an addition specific to Typomaniac: Monkeytype only knows starting at the first insertion (START-1), which remains the default behavior. It serves the duel, where both Players are timed from the same signal and reaction time matters. The sources cited below are the Monkeytype functions that anchor their computations to the start instant: the Start only moves that instant.

| Id       | Rule                                                                                                                                                                                                     | Source                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| START-2  | A Start applied to a Game that has not started starts the clock at its timestamp: the Game moves to the `running` status, without a Keystroke and without touching the inputs.                           | Typomaniac                                                                                   |
| START-3  | After a Start, the first insertion does not restart the clock: the time elapsed before the first letter counts in the duration (RES-1), so in the WPM and the Raw WPM (RES-2, RES-3).                    | Typomaniac, after `test/events/stats.ts` → `getTestDurationMs`                               |
| START-4  | In `time` Mode, the limit is counted from the Start when present (TICK-2, END-4).                                                                                                                        | Typomaniac, after `test/test-timer.ts` → `checkIfTimeIsUp`                                   |
| START-5  | A Start received when the Game has already started, through an insertion or a first Start, or is finished, is ignored.                                                                                   | Typomaniac                                                                                   |
| RES-6    | A Game finished without any Keystroke, which only happens in `time` Mode after a Start, has a Result: the Accuracy is 0 and the character count is zero, even with no Target word at all.                | `test/test-logic.ts` → `buildCompletedEvent` (`getAccuracy(...).percentage ?? 0`)            |
| DUEL-1   | Two Games are independent: created with the same words and the same Start then fed different Events, they give two Results that do not depend on each other. The engine keeps no state outside the Game. | Typomaniac (Monkeytype keeps its log in module variables, `test/events/data.ts`)             |
| REPLAY-1 | Replaying the same sequence of Events on a Game created the same way gives exactly the same Game, so the same Result and the same Keystroke log.                                                         | Typomaniac, after `test/events/stats.ts` (statistics derived from the log by pure functions) |
| REPLAY-2 | The Events and the Result contain only finite numbers, strings and arrays: a sequence of Events passed through JSON serialization then replayed gives the same Result and the same Keystroke log.        | Typomaniac                                                                                   |

Once the Start is received, the Game is `running` with an empty input: a deletion stays ignored there (DEL-2) and a space stays refused (INS-5). A Tick then counts from the Start, even before the first insertion (TICK-1 only holds as long as the clock has not started).

Known deviations on the Start:

- The engine does not compare an Event's timestamp to the Start's: an insertion timestamped before the Start is judged like the others. Bounding the client timestamps is the back end's role (out of scope).
- Monkeytype rounds each timestamp to 2 decimals of a millisecond (`test/events/data.ts` → `logTestEvent`). The engine keeps the received timestamp as is: a finite number crosses JSON without loss, so the replay stays identical.

## Per-second history

The Result cuts the Game into buckets and gives three integer series, one value per bucket. All instants are counted from the start of the Game (START-1 or START-2), not from the first Keystroke. The last bucket of the throughput history was re-read at the reference commit, as the spec requested: that is HIST-3 to HIST-5.

| Id     | Rule                                                                                                                                                                                                                                                                                                        | Source                                                                           |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| HIST-1 | The Game is cut into one-second buckets on a regular grid from the start: one per whole second elapsed at the end of the Game. The grid does not depend on the Ticks received. After a Start, the seconds elapsed before the first Keystroke are buckets like the others, empty.                            | `test/events/stats.ts` → `getTimerBoundaries`                                    |
| HIST-2 | A Keystroke belongs to the first bucket whose end boundary is greater than or equal to its instant: a Keystroke falling on a boundary goes in the bucket that ends there, the first Keystroke in the first. A Keystroke that arrived after the last boundary is in no bucket.                               | `test/events/stats.ts` → `countPerInterval`                                      |
| HIST-3 | In `words` Mode, an extra bucket is added at the end, from the last whole second to the end instant, if the remainder of the duration reaches 0.50 s. The remainder is read on the duration rounded to 2 decimals (RES-1): 3.994 s leaves 0.99 s, 3.996 s leaves nothing. Under 0.50 s, there is no bucket. | `test/events/stats.ts` → `getTimerBoundaries`                                    |
| HIST-4 | In `time` Mode, there is never an extra bucket: what is typed between the last whole second and the end Tick counts in the Result (END-5) but in no series.                                                                                                                                                 | `test/events/stats.ts` → `getTimerBoundaries`                                    |
| HIST-5 | Keystroke throughput series: the number of Keystrokes in the bucket (KEY-1), incorrect ones included, divided by 5 then by the bucket length in minutes, rounded to the integer. A one-second bucket is worth 12 per Keystroke; the extra bucket (HIST-3) is scaled to its real length.                     | `test/events/stats.ts` → `getBurstHistory` ; `utils/numbers.ts` → `calculateWpm` |
| HIST-6 | Error series: the number of incorrect Keystrokes in the bucket. An incorrect Keystroke erased afterwards stays counted where it was typed.                                                                                                                                                                  | `test/events/stats.ts` → `getErrorCountHistory`                                  |
| HIST-7 | Cumulative WPM series: at the end boundary of each bucket, the characters of the words typed exactly plus the correct beginning of the active word, from the input as it was at that instant, divided by 5 then by the time elapsed since the start in minutes, rounded to the integer.                     | `test/events/stats.ts` → `getWpmHistory`, `getChars` ; `inferActiveWordIndex`    |

Deviations from the text of the spec and of ticket #12, pending an answer from the spec author. Each follows Monkeytype and is reversed at the place indicated:

- **HIST-3, threshold of the extra bucket.** The spec says "if the remainder exceeds half a second"; the ticket says "reaches", and Monkeytype compares with "greater than or equal". The engine adds the bucket from 0.50 s inclusive. To go back to "exceeds": the comparison in `cutIntoBuckets` (`src/history.ts`).
- **HIST-7, active word credit in both Modes.** The spec and the ticket only credit the correct beginning of the active word in `time` Mode. `getWpmHistory` credits it whatever the Mode; only the final Result reserves it for `time` Mode (CHARS-6). The engine does as Monkeytype does. To go back to the text: the `creditActiveWord` option passed to `countChars` in `sampled` (`src/game.ts`).
- **HIST-5, refused Keystrokes.** The ticket says "incorrect and refused Keystrokes included". A refused insertion (INS-5, INS-7) is not a Keystroke (KEY-2): Monkeytype stops it before recording anything, and it is in no series. The series counts the Keystrokes of the log, incorrect ones included. To count refusals, they would first have to be recorded in the Game.

Known deviations on the history:

- Monkeytype replays its event log up to each boundary to recover the input at that instant. The engine's public log does not contain deletions (KEY-1): the Game instead keeps one sample per accepted insertion or deletion, with its instant and the characters credited at that instant, and HIST-7 reads the last sample at or before the boundary. These samples (`progress`) are an internal state of the engine, outside the public contract that the duel rules will read: that contract is limited to the Keystroke log and the Result.
- `getRawHistory` (cumulative Raw WPM per bucket) exists in Monkeytype; the spec does not ask for it, the engine does not compute it.
- A `words` Game whose rounded duration falls on a whole second while the real duration is just under it (3.996 s) has 3 buckets and no extra one: its last Keystroke is in no series. That is Monkeytype's behavior.

## Consistency

| Id     | Rule                                                                                                                                                                                                                              | Source                                                                                                     |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| CONS-1 | The Consistency is `100 × (1 − tanh(c + c³/3 + c⁵/5))`, where `c` is the population standard deviation of the Keystroke throughput series (HIST-5) divided by its mean. It is rounded to 2 decimals. A constant series gives 100. | `test/test-logic.ts` → `buildCompletedEvent` ; `packages/util/src/numbers.ts` → `kogasa`, `stdDev`, `mean` |
| CONS-2 | An undefined Consistency is 0: empty series (Game with no bucket) or zero mean (no Keystroke in any bucket, which only happens after a Start).                                                                                    | `test/test-logic.ts` → `buildCompletedEvent`                                                               |

Deviation from the text of the spec, pending an answer from the spec author. It follows Monkeytype and is reversed at the place indicated:

- **CONS-1, input series of the Consistency.** The spec says "the Keystroke throughput per second". `buildCompletedEvent` passes the formula the series from `getBurstHistory`, that is the throughput of each bucket expressed in WPM and rounded to the integer (HIST-5), extra bucket included (HIST-3). For one-second buckets, that is the number of Keystrokes multiplied by 12, which does not change the ratio of the standard deviation to the mean; the extra bucket, however, enters scaled to its real length then rounded, and can therefore shift the Consistency of a `words` Game. The engine does as Monkeytype does. To go back to the text: in `getResult` (`src/result.ts`), pass `consistency` the number of Keystrokes of each one-second bucket instead of `history.keystrokeRate`.

Known deviation on the Consistency: Monkeytype also computes a "WPM consistency" on the cumulative WPM series. The spec does not ask for it.

## Live stats

Live stats are read on a Game at an instant given by the caller: the engine has no clock. Monkeytype refreshes them on every Tick.

| Id     | Rule                                                                                                                                                                                           | Source                                                                                                         |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| LIVE-1 | The live WPM applies to the characters of the words typed exactly plus the correct beginning of the active word, divided by 5 then by the elapsed time in minutes, without rounding that time. | `test/test-timer.ts` → `timerStep` ; `test/events/stats.ts` → `getChars` ; `utils/numbers.ts` → `calculateWpm` |
| LIVE-2 | The live Raw WPM applies to the correct, incorrect and extra characters (CHARS-1 to CHARS-4, CHARS-8), with the same formula.                                                                  | `test/test-timer.ts` → `timerStep`                                                                             |
| LIVE-3 | The live WPM and Raw WPM are rounded to the nearest integer.                                                                                                                                   | `states/live-stats.ts` → `getLiveSpeedText`                                                                    |
| LIVE-4 | The live Accuracy is the correct Keystrokes over the total Keystrokes (ACC-1), as a percentage truncated to the lower integer.                                                                 | `test/events/live-cache.ts` → `getLiveCachedAccuracy` ; `states/live-stats.ts` → `getLiveAccText`              |
| LIVE-5 | The live stats of a Game that has not started are all 0, without error. As long as no time has elapsed, the speeds are 0 (RES-4); as long as there is no Keystroke, the Accuracy is 0.         | Criterion of ticket #12 ; `utils/numbers.ts` → `calculateWpm`                                                  |
| LIVE-6 | The elapsed time is counted from the start of the Game (START-1 or START-2) to the requested instant. For a finished Game, it stops at the end instant: its live stats no longer move.         | `test/events/live-cache.ts` → `getLiveCachedTestDurationMs` ; the frozen end is a Typomaniac choice            |

Deviations from the text of the spec and of ticket #12, pending an answer from the spec author:

- **LIVE-1, active word credit in both Modes.** `timerStep` calls `getChars` forcing the active word credit, whatever the Mode; the spec only provides for it in `time` Mode. The engine does as Monkeytype does. To go back to the text: the `creditActiveWord` option passed to `measureTyping` in `getLiveStats` (`src/live-stats.ts`).
- **LIVE-4, Accuracy truncated to the lower integer.** The spec and the ticket say "rounded to the integer" for the three stats. Monkeytype rounds the speeds but truncates the displayed Accuracy: 81.82% is displayed as 81. The engine does as Monkeytype does. To go back to the text: `Math.floor` in `getLiveStats`.
- **LIVE-5, Accuracy 0 before the first Keystroke.** Here the engine follows the ticket's criterion ("are 0") and not Monkeytype, which displays 100 as long as there is no Keystroke. The same value 0 applies to a Game launched by a Start and still without a Keystroke, like the Result's Accuracy (RES-6). To follow Monkeytype: handle the no-Keystroke case in `getLiveStats`, the 0 value of `measureTyping` (`src/chars.ts`) also serving the Result.

## Keys

A key press and a key release describe the physical rhythm of typing: they carry an instant and the key code. The engine judges nothing with them: this data will serve the back end. The computation of the gaps between key presses was re-read at the reference commit, as the spec requested: that is PRESS-2, GAP-1 and GAP-2.

| Id      | Rule                                                                                                                                                                                                                                                                 | Source                                                                                                                     |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| PRESS-1 | A key press or release changes neither the input, nor the Keystroke log, nor the status, nor the clock: a key press received before the first insertion does not start the Game (START-1). The Game keeps every key press received, with the release that closed it. | `input/handlers/keydown.ts` → `onKeydown` ; `input/handlers/keyup.ts` → `onKeyup` ; `test/events/data.ts` → `logTestEvent` |
| PRESS-2 | Of the key presses before the start of the Game, the Result keeps only the last one: it is the one that produces the first insertion. After a Start, the key presses that precede the first insertion follow the Start: they are all kept.                           | `test/events/data.ts` → `cleanupData`                                                                                      |
| PRESS-3 | A release with no key press in progress for the same key is ignored: the Game does not change.                                                                                                                                                                       | `test/events/data.ts` → `logTestEvent`                                                                                     |
| PRESS-4 | A key press on a key already held, whose release was lost, closes the first press at the instant of the second.                                                                                                                                                      | `test/events/data.ts` → `logTestEvent`                                                                                     |
| GAP-1   | The Result contains the series of gaps between consecutive key presses, in milliseconds, whatever the key: N key presses give N − 1 gaps. Without a key press, the series is empty.                                                                                  | `test/events/stats.ts` → `getKeypressSpacing`                                                                              |
| GAP-2   | The gap that follows the key press kept from before the start (PRESS-2) is measured from the start, not from that key press.                                                                                                                                         | `test/events/stats.ts` → `getKeypressSpacing`                                                                              |
| HOLD-1  | The Result contains the series of key hold durations, in milliseconds: one entry per kept key press, in key press order, from the press to the next release of the same key. The key press kept from before the start is measured from its real instant.             | `test/events/stats.ts` → `getKeypressDurations`                                                                            |
| HOLD-2  | A key never released gets as its duration the mean of the strictly positive durations of the released key presses of the Game, rounded to 2 decimals, or 80 ms if there are none.                                                                                    | `test/events/data.ts` → `forceReleaseAllKeys`, called by `test/test-logic.ts` → `finish`                                   |
| HOLD-3  | A release before the start does not count: if the key press kept from before the start (PRESS-2) was released, or is estimated released (HOLD-2), before the start, its duration is 0.                                                                               | `test/events/data.ts` → `cleanupData` ; `test/events/stats.ts` → `getKeypressDurations`                                    |
| KCONS-1 | The Key consistency applies the Consistency formula (CONS-1) to the series of gaps between key presses (GAP-1) minus its last gap. It is rounded to 2 decimals.                                                                                                      | `test/test-logic.ts` → `buildCompletedEvent` ; `packages/util/src/numbers.ts` → `kogasa`, `stdDev`, `mean`                 |
| KCONS-2 | An undefined Key consistency is 0: no gap, or a single one, which is removed.                                                                                                                                                                                        | `test/test-logic.ts` → `buildCompletedEvent`                                                                               |

A key press or release applied to a finished Game does not modify it (END-2). The key presses made between the limit of a `time` Game and the Tick that ends it count, like the Keystrokes (END-5).

Deviations from the text of ticket #13, pending an answer from the spec author. Each follows Monkeytype and is reversed at the place indicated:

- **PRESS-2, key presses from before the start.** The ticket says "the series of gaps between consecutive key presses", without excluding any key press. `cleanupData` only keeps the last of the key presses before the start: the others are neither in the gap series nor in the duration series, and N key presses received can give fewer than N − 1 gaps. Keys pressed before the Player begins say nothing about the rhythm of their Game. The engine does as Monkeytype does. To go back to the text: return all the key presses of the Game in `countedKeyPresses` (`src/keys.ts`).
- **GAP-2, first gap measured from the start.** The ticket says the gap between two consecutive key presses. `getKeypressSpacing` brings the instant of the key press kept from before the start back to the start: the first gap is the time between the start and the second key press, so that the sum of the gaps stays the time played. The engine does as Monkeytype does. To go back to the text: remove the `Math.max(startedAt, …)` bound from `keyPressGaps` (`src/keys.ts`).
- **HOLD-3, duration 0 for a key press released before the start.** The ticket says each release is associated with the key press of the same key, which would give that key press its real duration. `cleanupData` discards all releases before the start, and `getKeypressDurations` then leaves the key press its initial value, 0. The engine does as Monkeytype does. To go back to the text: remove the comparison to `startedAt` at the end of `keyHoldDurations` (`src/keys.ts`).

- **HOLD-2, key never released.** The ticket says a key press never released is ignored. Monkeytype does not ignore it: at the end, `forceReleaseAllKeys` invents a release, and `getKeypressDurations` always returns one entry per key press, which keeps the duration series aligned with the gap series (duration i is that of key press i, gap i goes from key press i to key press i + 1). The engine does as Monkeytype does. A release with no key press stays ignored (PRESS-3), as the ticket says. To go back to the text: remove from `keyHoldDurations` (`src/keys.ts`) the key presses whose `releasedAt` is `null`, instead of giving them the estimate.

Known deviations on keys:

- Monkeytype only records a fixed list of keys (`test/events/helpers.ts` → `keysToTrack`: letters, digits, punctuation, space, Enter, tab, numeric keypad) and discards auto-repeats before recording anything. Backspace, Delete and modifier keys are therefore never in it. The ticket does not ask for this filter: the engine records every key press received, and it is up to the emitter not to send keys outside the list nor repeats. A repeat received anyway is handled by PRESS-4.
- To estimate a release (HOLD-2), `forceReleaseAllKeys` associates with each key only its first release and its last key press: a key pressed several times gives a negative duration, which it discards, and its mean in practice covers only keys pressed once. The engine takes the mean of all released key presses, as the rule describes. The estimated value can therefore differ from Monkeytype's.
- Monkeytype sorts its events by instant, and at equal instants places a release before a key press. The engine keeps the order in which it receives the Events.
- `cleanupData` also discards key presses after the end. The engine never receives them: an Event applied to a finished Game is ignored (END-2).

## Inactivity

Inactivity is read on the history buckets (HIST-1 to HIST-4), extra bucket included. The engine judges nothing: it returns a duration and a flag, and it is the back end that will decide whether a Result can be recorded.

| Id     | Rule                                                                                                                                                                                                                                                                  | Source                                                                               |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| IDLE-1 | The Inactivity duration is the number of buckets with no kept key press (PRESS-2), no accepted insertion and no accepted deletion. It is a whole number of buckets: the extra bucket counts for one. The key press kept from before the start is in the first bucket. | `test/events/stats.ts` → `getAfkDuration`, `countPerInterval`, `getTimerBoundaries`  |
| IDLE-2 | The final Inactivity is true if none of the last 5 buckets contains a Keystroke (KEY-1), false otherwise. Key presses and deletions do not count there, nor does what is typed after the last bucket.                                                                 | `test/test-logic.ts` → `finish` ; `test/events/stats.ts` → `getKeypressesPerSecond`  |
| IDLE-3 | A Game of fewer than 5 buckets is judged on all its buckets. With no bucket at all, the final Inactivity is true and the Inactivity duration is 0.                                                                                                                    | `test/test-logic.ts` → `finish` (`slice(-5)` then "all zero", true on an empty list) |

Deviations from the text of the spec and of ticket #13, pending an answer from the spec author. Each follows Monkeytype and is reversed at the place indicated:

- **IDLE-1, a deletion is an activity.** The spec and the ticket say "with no key press or insertion". `getAfkDuration` counts every input event, deletions included: backspace is not a key recorded by Monkeytype, and only the deletion keeps a second spent erasing from being inactive. The engine does as Monkeytype does, for an accepted deletion; an ignored deletion (DEL-2, DEL-4) is not an activity. To go back to the text: in `getResult` (`src/result.ts`), read the activity instants from the key presses and the Keystroke log instead of the key presses and the `progress` samples.
- **IDLE-3, Game with no bucket.** The ticket refers to "the rule found in Monkeytype" for a Game of less than 5 seconds: the existing buckets are all taken into account, and if there are none the flag is true. A `words` Game of less than 0.495 s, or lasting between 0.995 s and 1 s (HIST-3), is therefore inactive at the end although the Player typed to the end. The engine does as Monkeytype does. To make it false with no bucket: the condition of `inactiveAtEnd` in `getResult`.

Known deviations on Inactivity:

- A `words` Game whose end falls in no bucket (7.30 s: 7 buckets, no extra bucket) can be inactive at the end although its last Keystroke ends it. That is Monkeytype's behavior.
- Monkeytype subtracts the Inactivity duration from the duration to get the time actually spent typing, and a true flag makes the result invalid there. The engine only returns the two values.
